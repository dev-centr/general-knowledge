= Connect Cloudflare in Composio
:navtitle: Composio Cloudflare connection
:description: Pick the right Composio Cloudflare toolkit—OAuth vs API key—and match Cloudflare credential types so agents can list zones and change DNS without 9109 errors.

Use this when an agent needs **Cloudflare DNS, zones, or Access** through Composio (custom domains, `team.docs` hostnames, email MX, orange-cloud vs grey-cloud). MCP install is separate: xref:how-to/composio-mcp-setup.adoc[Composio MCP setup].

Credential vocabulary: xref:explanation/infrastructure/api-key-vs-token.adoc[API key vs token]. GitHub Pages + Cloudflare HTTPS: xref:how-to/github-pages-custom-domain.adoc[GitHub Pages custom domain].

== Two Composio apps that look the same

Composio lists **Cloudflare** and **Cloudflare API Key** as nearly identical catalog entries. They are **not** interchangeable.

[cols="1,2,2", options="header"]
|===
| Composio toolkit | Auth it actually wants | Use when

| **Cloudflare**
| **OAuth** — browser consent; Composio stores a Cloudflare *access token*
| You can complete Cloudflare’s OAuth screen. Prefer this if the grant stays healthy.

| **Cloudflare API Key**
| Dashboard secret — **email + Global API Key**, *or* a Cloudflare **API Token** (scoped long-lived key), depending on the form fields
| OAuth is broken, you already mint API tokens, or you need a machine-style key
|===

Connect **one**. Do not paste a Global API Key or API Token into the **OAuth** app. The OAuth form will often accept the paste, mark the connection **ACTIVE**, and then every zone call fails with Cloudflare **`9109 Invalid access token`**. Composio has no “refresh” for that — the stored credential is the wrong *kind*. Disconnect and use the matching toolkit.

== Match the form to the Cloudflare secret

Cloudflare’s dashboard also overloads “token.” Decision test (ignore button labels):

[cols="1,2,2", options="header"]
|===
| What you copied | Architectural type | Composio field

| Browser OAuth / “Allow Composio”
| Access token (handshake-issued)
| **Cloudflare** (OAuth) only

| **API Token** from My Profile → API Tokens (scoped, lives until revoked)
| Scoped API key (vendor still says “token”)
| **Cloudflare API Key** — the single Bearer / API Token field

| **Global API Key** + account **email**
| Unscoped API key
| **Cloudflare API Key** — email + Global API Key fields, not the OAuth app
|===

If the form asks for email + Global API Key, do not put an API Token in the key box (or vice versa).

Minimum scopes for DNS work on an API Token:: `Zone:Read` to list; `Zone:Edit` (DNS) to create/update records. Add **Access** scopes only if the agent must manage Access apps.

== ACTIVE is not a smoke test

Composio **ACTIVE** means “we stored *something*.” It does not mean Cloudflare accepted it.

. After connect, run a real list: zones for the intended domain (e.g. `devcentr.org`).
. Success: zone `id`, `name`, `status`.
. **`9109 Invalid access token`** — wrong toolkit or wrong secret kind. Disconnect, reconnect on the other app, match the table above.
. **`10502 Too many authentication failures`** — Cloudflare rate-limited the bad attempts. Wait several minutes; do not hammer retries.

Machine does not matter. Composio stores the credential server-side; a connection that “worked on the laptop” is the same object on every studio.

== After it lists zones

Typical next steps (confirm with the user before writes):

. List DNS records on the zone (`name` filter for the hostname).
. Create or update records only after an explicit go-ahead.
. For GitHub Pages custom domains, keep the Pages hostname **DNS-only (grey cloud)** while GitHub issues Let’s Encrypt — see xref:how-to/github-pages-custom-domain.adoc[GitHub Pages custom domain].

= How-to Guides
:description: Task-oriented guides for common developer setup and workflow problems.

Task-oriented guides. Pick a guide when you already know what you want to do.

== Featured

* xref:how-to/secrets-distribution-cli-mcp.adoc[Secrets distribution (CLI · MCP)] — Vault custom fields → local env → hosting env; hub later so matrix changes are not retyping. Tutorial: xref:tutorials/secrets-from-vendor-to-deploy.adoc[From vendor dashboard to deploy matrix].
* xref:how-to/composio-mcp-setup.adoc[Composio MCP setup] — Connect Gmail / GitHub / Vercel tools to Cursor for CI mail triage; finish with a real fetch, not install-only. Pattern for shipping similar tooling: xref:explanation/infrastructure/studio-mcp-install-strategies.adoc[Studio MCP install strategies]. Duplicate catalog entries: xref:how-to/composio-mcp-setup.adoc#duplicate-toolkits[read the form]. Cloudflare DNS/Access: xref:how-to/composio-cloudflare-connection.adoc[Connect Cloudflare in Composio].
* xref:how-to/google-cloud-oauth-for-personal-tools.adoc[Google Cloud OAuth for personal tools] — Project + consent + Client ID when Composio (or rclone) asks for credentials; mental model: xref:explanation/infrastructure/google-cloud-project-mental-model.adoc[Google Cloud projects as OAuth boundaries].
* xref:agent-rules::gcloud-cli-agents.adoc[gcloud CLI for agentic workflows] — Cloud SDK login persistence for agents (separate from OAuth Client IDs).
* xref:agent-rules::bitwarden-cli-agents.adoc[Bitwarden CLI for agentic workflows] — optional vault session persist for agents.
* xref:how-to/context7-mcp-setup.adoc[Context7 MCP and Skills setup] — Library/API docs MCP for version-sensitive agent work.
* xref:how-to/bootstrap-cursor-skills.adoc[Bootstrap Cursor skills] — Personal Agent Skills without clogging always-on User Rules; YAML `description` is trigger words, not a lay blurb (skill `write-a-skill`). Operator path or drop the recipe into a permissive agent. Framing: xref:explanation/infrastructure/vibe-coding-bootstrap.adoc[Vibe coding bootstrap].
* xref:business-bootstrap::tutorials/fast-org-bootstrap.adoc[Fast org bootstrap] — GitHub org identity (profile, site, docs hub) as an agent skill; capability-area IT stays in Business Bootstrap. Not the same as installing Cursor skills.
* xref:how-to/nushell-setup.adoc[Install and set up Nushell] — Default shell for Dev-Centr on every OS.
* xref:how-to/wsl-setup.adoc[Set up and manage WSL] — Enable WSL, pick a default distro, open WSL Settings.
* xref:how-to/flutter-setup.adoc[Set up Flutter tooling] — SDK bootstrap; community version bridges until an official Toolchain Control Plane exists (see Toolchain Management Pattern).
* xref:how-to/github-pages-custom-domain.adoc[GitHub Pages custom domain + Cloudflare HTTPS] — Grey-cloud for GitHub LE; poll Pages API; companion `scripts/check-gh-pages-https.nu`.
* xref:how-to/cloudflare-access-static-site.adoc[Protect a static site with Cloudflare Access] — Member-only hostname; GitHub org / Google / one-time PIN; cover `*.pages.dev` too. Setup order (OAuth App UI → IdP → policy → apps), team-name callback, Pages-token 403s. Why: xref:explanation/infrastructure/access-in-front-of-static-sites.adoc[Access in front of static sites].
* xref:how-to/finding-windows-internals-docs.adoc[Finding Windows internals documentation] — Learn / MSDN-shaped trees, MicrosoftDocs GitHub, search when wording differs.

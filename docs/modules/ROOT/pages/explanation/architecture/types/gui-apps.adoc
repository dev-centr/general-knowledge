== Must-ship surfaces

* **Help** — docs entry, shortcuts, report issue
* **About** (menu: Help → About, or app menu on macOS) with version, build id, channel — xref:explanation/architecture/about-and-build-info.adoc[About and build info]
* **Debug dump** button on that dialog — xref:how-to/about-screen-and-debug-dump.adoc[How-to]
* **Settings** with paths to logs/config or a “Open logs folder” action
* **Update** affordance — check now / restart to update — xref:explanation/architecture/automatic-updates.adoc[Automatic updates]
* **Installer** with uninstall (desktop) — xref:explanation/architecture/distribution-and-packaging.adoc[Distribution]

== Desktop OS emphasis

* **Windows:** MSI/MSIX or winget-friendly installer; code-sign; auto-update or Store/winget before 1.0 — xref:how-to/windows-auto-updates.adoc[Windows auto-updates], xref:how-to/winget-registration.adoc[Winget]
* **macOS / Linux:** prefer Store/Sparkle/Homebrew or distro/Flatpak/AppImage; quit → replace → relaunch (never overwrite a running ELF) — xref:how-to/unix-auto-updates.adoc[Unix/macOS auto-updates]

== Rendering and framework choice

Pick a UI stack with enough **rendering headroom** for how long the client stays open and how large in-app documents grow (chat, mail, live logs).
Electron and Chromium shells excel at ecosystem reach; retained-mode native stacks (Avalonia, Qt, Flutter, GPUI) avoid DOM/V8 overhead for dense, long-lived surfaces.

* xref:explanation/architecture/graphics-rendering-engines.adoc[Graphics rendering engines] — comparison tables, large-document patterns, and what comes after Skia (Graphite, Impeller, Vello)

== UX notes

* Do not hide version solely in logs
* First-run may mention crash reporting opt-in; do not bury it forever
* High-DPI, accessibility, and keyboard paths are product quality—not separate from “essentials,” but tracked in your UI standards

== Mobile

Stores own distribution and updates; you still need in-app version display, Help, log export for support, permission rationales, and crash reporting (opt-in where required by policy). Full list: xref:explanation/architecture/classes/mobile.adoc[Mobile template].

== Checklist

* [ ] Help reachable (docs + report issue)
* [ ] About shows version + build id + channel
* [ ] Dump button produces redacted zip
* [ ] Update path live on every supported desktop OS
* [ ] Signed installer + uninstall (desktop)
* [ ] Open logs / config from UI
* [ ] Changelog linked from About or Help
* [ ] Class template rows triaged (desktop and/or mobile)

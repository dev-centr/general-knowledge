= Internet Reliability
:description: Usability of the internet and reference durability—machine, developer-ecosystem, and internet altitudes under Internet Architecture.

**Internet Reliability** is a slice of xref:explanation/internet-architecture/index.adoc[Internet Architecture].
It is broader than network uptime: it includes whether people and tools can still *find and use* the thing they meant after names, hosts, and paths move.

People usually arrive with a rename that broke half their docs, or a URL that went cold.
HCI Nerdz writes that pain and the diagnosis in ordinary language — start with link:https://hci-nerdz.github.io/blog/broken-links-after-a-url-rename/[Broken links after a URL rename].
This hub zooms out: how the same mistake scales from a single machine to a developer ecosystem to the public internet.

image::internet-architecture/three-altitudes.svg["Three nested altitudes: machine, developer ecosystem, internet",width=720]

== What counts as reliability here

[cols="1,2"]
|===
| Layer people mean | What Internet Reliability adds

| Packet / host uptime
| Necessary, not sufficient — a 200 on the wrong identity is still a broken reference

| Docs and API URLs
| Reference durability: citations, `xref:`, READMEs, agent trees keep resolving

| Developer experience
| Ecosystem reliability: renames are search-and-fix under known consumers, not org-wide archaeology

| Human usability of the web
| The internet remains usable as a shared memory, not only as a transport
|===

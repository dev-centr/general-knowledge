Use this table when a diff, page or log shows short runs of accented capitals and currency symbols where punctuation should be.
Each row is one original character, its UTF-8 bytes, what it turns into after one read-as-Windows-1252-and-save cycle, and the bytes now on disk.
Why it happens: xref:explanation/infrastructure/text-encoding-and-ai-agents.adoc[Text encoding and AI agents].
Prevention: xref:how-to/prevent-text-encoding-corruption.adoc[Prevent text encoding corruption].

Two rounds (the corrupted file read and saved wrongly a second time) roughly double the length again; you will see long runs of `&#195;` and `&#194;` between the remnants of the original text.

== Guard signatures

Three byte prefixes cover almost every case and almost never appear in legitimate text:

[cols="1,2,3",options="header"]
|===
| Bytes | Looks like | Produced by

| `C3 A2 E2 82 AC`
| `&#226;&#8364;` followed by one more symbol
| Characters encoded `E2 80 xx` in UTF-8 (General Punctuation): dashes, curly quotes, ellipsis, bullet

| `C3 83 C2`
| `&#195;` followed by a Latin-1 symbol
| Accented Latin letters encoded `C3 xx` (`&#233;`, `&#252;`, `&#241;`, ...)

| `C3 82 C2`
| `&#194;` followed by a Latin-1 symbol or space
| Characters encoded `C2 xx`: no-break space, degree, copyright, section sign
|===

Other three-byte ranges also start with `&#226;` but continue differently (arrows `E2 86 xx` become `&#226;&#8224;` plus a symbol; box drawing `E2 94 xx` becomes `&#226;&#8221;` plus a symbol). Add signatures for those if your files use them.

Build them from escapes so the script itself stays ASCII:

[source,bash]
----
sig_lead=$(printf '\303\242\342\202\254')
sig_atilde=$(printf '\303\203\302')
sig_acirc=$(printf '\303\202\302')
git grep -nIF -e "$sig_lead" -e "$sig_atilde" -e "$sig_acirc"
----

Related byte-level problems a guard should also reject or warn about:

[cols="1,2,2",options="header"]
|===
| First bytes | Meaning | Typical source

| `FF FE` or `FE FF`
| UTF-16 (or UTF-32) text; Git treats it as binary
| Windows PowerShell 5.1 `Out-File` or `>` redirect

| `EF BB BF`
| UTF-8 with a byte-order mark
| Windows PowerShell 5.1 `-Encoding UTF8`, some Windows editors; breaks shebang lines and some parsers

| Lone bytes `80`-`FF` that are not valid UTF-8
| Windows-1252 or Latin-1 bytes in a file that claims UTF-8
| `Set-Content` default (ANSI) in 5.1; hand-authored SVG labels
|===

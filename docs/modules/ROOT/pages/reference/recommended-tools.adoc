= Recommended Development Tools
:navtitle: Recommended Tools
:description: Recommended platform, shell, package, and workflow tools for Dev-Centr developers.

We recommend these tools for a consistent, cross-platform developer workflow.

== Platform & Shell

* link:https://www.nushell.sh/[**Nushell**] — **Required recommendation.** Default interactive and scripting shell on Windows, macOS, and Linux. Structured pipelines; display owned by the shell at the end of the pipe. See xref:explanation/infrastructure/nushell.adoc[Why We Recommend Nushell] and xref:how-to/nushell-setup.adoc[setup].
* link:https://aka.ms/terminal[Windows Terminal] — Modern terminal host on Windows; add a profile that launches `nu`.
* link:https://www.warp.dev/[Warp] — Optional modern terminal with strong UX (where you choose it).
* link:https://learn.microsoft.com/en-us/windows/advanced-settings/sudo/[`sudo` for Windows] — Elevate when the OS requires it.
* PowerShell 7 — Use only when an OS feature, installer, or legacy script demands it. **Not** the Dev-Centr default shell.

== Package Management

* link:https://www.marticliment.com/unigetui/[UniGetUI] — GUI over `winget` and other managers (Windows).
* link:https://pnpm.io/[pnpm] — Preferred Node package manager in this ecosystem.
* link:https://bun.sh/[Bun] — Practical OSS Node-shaped runtime + package manager when you want speed in one tool; see xref:explanation/infrastructure/npm-package-managers.adoc[npm package managers].
* **Orogene** — Catalogued as *closed-aspirational* (once and future king of `node_modules/` installs if it re-open-sources); not a shop default while closed. Same comparison page.
* link:https://docs.astral.sh/uv/[uv] — Preferred Python environment and package tool.
== Editors & Agents

* link:https://cursor.com/[Cursor] — Primary AI-assisted IDE in this workspace.
* link:https://code.visualstudio.com/[VS Code] — Acceptable when Cursor is unavailable.
* link:https://composio.dev/[**Composio**] — Hosted MCP connectors (Gmail, GitHub, Vercel, Cloudflare, …) for cross-app agent work. Prefer for **CI mail triage** and similar OAuth SaaS loops; still use `gh` / the shell for PATH-local forge ops. See xref:how-to/composio-mcp-setup.adoc[setup], xref:how-to/composio-cloudflare-connection.adoc[Cloudflare connection], xref:explanation/infrastructure/composio-and-mcp-connectors.adoc[stack fit], and xref:explanation/infrastructure/studio-mcp-install-strategies.adoc[studio install pattern]. Duplicate catalog names: xref:how-to/composio-mcp-setup.adoc#duplicate-toolkits[read the form].
* link:https://bitwarden.com/help/cli/[**Bitwarden CLI**] (`bw`) — Human vault + custom fields for API keys; pair with hosting CLIs for distribution. Pattern: xref:explanation/infrastructure/secrets-distribution-hub.adoc[Secrets distribution hub], xref:how-to/secrets-distribution-cli-mcp.adoc[how-to]. Hosting choice (cloud vs official server vs Vaultwarden): xref:business-bootstrap::vault/explanation/bitwarden-and-vaultwarden.adoc[Bitwarden and Vaultwarden].
* link:https://vercel.com/docs/cli[**Vercel CLI**] — Prefer `pnpm add -g vercel` when winget lacks the package; use team `--scope` after org moves.
* **Standalone agent shells** — Do not treat the IDE as the only control plane. For shopping, hardware fit, and local / network-local / remote-env / three-tier topologies, see xref:explanation/infrastructure/agent-control-planes.adoc[Agent control planes] and DevCentr’s `agent_shell_registry.sdl`. Setup surface: **AI Workflow Arrangement** (icons + diagrams in AI Config — not a wizard). Keep DevCentr’s env-aware repo terminal as the always-on human ops shell; agent-manager PTYs are not a substitute.
* **AI studio tooling map** — Master list of MCP/connectors/control-plane docs: xref:reference/ai-studio-tooling-catalog.adoc[AI studio tooling catalog].

== Fonts (monospace)

Strong recommendation for terminals, editors, and DevCentr code panels:

* link:https://github.com/microsoft/cascadia-code[**Cascadia Mono**] — **Default.** No ligatures; best for tables/grids (including Nushell `table` output). Prefer Mono over Cascadia *Code*.
* link:https://www.jetbrains.com/lp/mono/[**JetBrains Mono**] — Supported alternate in DevCentr Appearance settings.

DevCentr lets you pick between those two (Appearance in the top bar). Install the font on the OS so editors and Windows Terminal can use it too.

== Design & Brand Motion

UI/brand **canvas**: prefer xref:business-bootstrap::design/explanation/penpot.adoc[Penpot] when the team wants an open design platform; stay on Figma when partners already live there.

No single **motion** format wins. Choose by job (see xref:explanation/brand-motion.adoc[Brand and UI Motion Formats] for the full matrix):

* link:https://www.w3.org/Graphics/SVG/[**Animated SVG**] — **Default** for portable brand motion (org profiles, docs, marketing without a JS player). Prefer a self-contained file that honors `prefers-reduced-motion`. Best agentic/git fit.
* link:https://airbnb.design/lottie/[**Lottie**] — Use when motion is complex *baked* timeline work (often After Effects). JSON is text but cumbersome to edit; needs a player. Acceptable in AE pipelines (including CentrMark’s Lottie support); **not** the automatic default for simple marks.
* link:https://rive.app/[**Rive**] — Option for *interactive* / theme-driven UI motion (state machines, inputs) when a runtime is justified. Runtimes MIT; **editor proprietary**; **`.riv` is binary** (weak agentic authoring). Prefer lite packages when possible; lazy-load. **Do not** treat as an open de facto standard.

Watch-only (not endorsed defaults): text-first motion DSLs / CSS-shaped scene formats aimed at LLM workflows — see the explanation page. **Popkorn** is noted there as a *potential future* solution; outreach: link:https://github.com/ayarse/popkorn/issues/7[ayarse/popkorn#7].
